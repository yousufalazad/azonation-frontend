How every session works

  1. Start: you open a new session in the project folder and paste the start message below.
  2. Read: I read CLAUDE.md, the roadmap and the latest handoff note, so there's no need to explain anything again.
  3. One task: I work on the next step only (for example "move Meetings"), using the old code as the reference.
  4. Check: before finishing, I build, run the tests and try it in the browser in light and dark mode, on a phone-sized screen and in more than one language.
  5. Save: I tick the inventory items, update the roadmap and write a short handoff note, then commit and push to GitHub.
  6. Report: I tell you in plain words what's done, what to test and what I need from you.

Start message for every new session:

Read CLAUDE.md, docs/ROADMAP.md and the newest note in docs/handoff/, then continue.

Already decided

  • Modular monolith: one Laravel API and one Vue app, split into modules
  • Old repos frozen; move module by module, nothing missed
  • Sanctum session login; JWT or OAuth added later if needed
  • Sign-in: email, Google, Microsoft, Apple
  • 10 languages from the start, including right-to-left
  • Band pricing: monthly price per package per region, with member limits
  • Azonation never holds organisations' money
  • azonation.com (site, app, api) · azonation.org (organisation sites) · azonation.net (files, mail)
  • Community kept small, with no social feed
  • No stored procedures
Tip to keep costs down: keep one task per session, and use Sonnet for module moves once the first one sets the pattern. Opus is worth it for the foundation, Billing, security and anything unclear.
